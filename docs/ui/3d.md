# 3D views

`@repo/ui-3d` draws an interactive 3D view in the web and desktop apps: a React Three Fiber canvas inside an accessible viewer that a DOM control drives. The agent workflow is the `kaine-build-3d` skill.

## When to use 3D

Use 3D only when spatial understanding is the task: where a finding sits on a body, how parts of a device fit together, what a room looks like from another side. If a flat diagram, a chart, or a list answers the question, use that instead. 3D costs about 200 KB of script, a GPU, and battery, and it is harder to make accessible.

Data and selection state live in React and in the DOM, never in the scene. The scene draws that state; it does not own it.

## Set up an app

1. Add `@repo/ui-3d` to the app's dependencies. A workspace that writes a scene also adds `three` and `@types/three` with `catalog:` (upgrade the two together).
2. Import `@repo/ui-3d/styles.css` in place of `@repo/ui/styles/globals.css` in the app entry. It is the same stylesheet plus the package's class names, which Tailwind would not scan otherwise.

## Build a view

Three files: the screen, a scene module that the screen loads lazily, and the control that holds the state.

```tsx
// region.screen.tsx: no three.js here
import { Viewport3D } from "@repo/ui-3d";
import { lazy, useState } from "react";

const RegionScene = lazy(() => import("./region.scene"));

function RegionView() {
  const [region, setRegion] = useState<RegionId | null>("left-knee");

  return (
    <>
      <Viewport3D
        announcement={region ? t("regions.selected", { region: label(region) }) : t("regions.none")}
        className="aspect-square w-full"
        fallback={<RegionPoster />}
        labels={viewerLabels /* translated: viewer, keyboardHelp, controls, rotateLeft, … */}
        onClearSelection={() => setRegion(null)}
      >
        <RegionScene selected={region} onSelect={setRegion} />
      </Viewport3D>
      <RegionPicker selected={region} onSelect={setRegion} /> {/* the real control */}
    </>
  );
}
```

```tsx
// region.scene.tsx: everything that imports three
import { useThemeMaterials } from "@repo/ui-3d/scene";

const TOKENS = { base: "--ds-text", highlight: "--ds-background-selected-bold" } as const;
const OPTIONS = { keepColor: ["highlight"] } as const;

export default function RegionScene({ selected, onSelect }: RegionSceneProps) {
  const materials = useThemeMaterials(TOKENS, OPTIONS);
  // shared geometries in useMemo, disposed in an effect cleanup
  return regions.map((region) => (
    <mesh
      key={region.id}
      geometry={geometries[region.solid]}
      material={region.id === selected ? materials.highlight : materials.base}
    />
  ));
}
```

### `@repo/ui-3d`

| Export                               | What it does                                                                                                                                                                                                     |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Viewport3D`                         | The viewer. Lazy canvas, focusable region, keyboard, turn and zoom buttons, live region, reduced motion, fallback, context-loss handling, demand rendering, and `data-render-stats`. Its text comes in `labels`. |
| `supportsWebGL2()`                   | The WebGL2 probe the viewer runs before it mounts a canvas.                                                                                                                                                      |
| `RenderStats`, `View`, `Viewport3D*` | Types.                                                                                                                                                                                                           |
| `useThemeMaterials` (`/scene`)       | One shared Lambert material per state from `--ds-*` tokens. Follows theme changes, asks for a frame, and disposes on unmount. `keepColor` draws a material unlit, in exactly its token color.                    |
| `useThemeColors` (`/scene`)          | The theme bridge under it: tokens to `THREE.Color` and opacity, read from the canvas, again whenever `data-theme` or `data-color-mode` changes on `<html>`.                                                      |

The root entry never imports three.js; `/scene` does, so import it only from the lazy scene module. Files that draw three.js elements end in `.scene.tsx`: the lint config treats their lowercase elements as three.js objects, not DOM elements.

`Viewport3D` centers the model, fits the camera to it (zoom 1 shows all of it from any side), and turns it around the vertical axis. Pass `tilt` with its button labels to allow tilting, `zoom` to change the 0.75–3 range, and `initialView` for the start angle.

## Accessibility

Rule A11Y-8 in `docs/ui/guidelines.md`. `Viewport3D` does the first five; the screen does the rest.

- The canvas is `aria-hidden`. The viewer is a focusable region with your `labels.viewer` and `labels.keyboardHelp`, and a `border-focused` ring.
- Arrow Left and Right turn the model, Up and Down tilt it (only with `tilt`), `+` and `-` zoom, Home resets, and Escape calls `onClearSelection`.
- Turn, zoom, and reset buttons are the alternative to dragging. They stack at the bottom start corner: keep that corner free and give the viewer about 300px of height on phones, where the buttons are 44px.
- `announcement` is read in a polite live region when it changes.
- Reduced motion snaps camera moves and follows changes to the setting. The viewer never turns by itself.
- A DOM control beside the viewer holds the selection, with translated names: a radio group, a list, or a select.
- The highlight reaches 3:1 against the base material and the background in both modes. Measure the token pairs in a theme test, and pass the highlight in `keepColor`: lit faces shade down to 70% of their color, so a base that is lighter than the highlight needs about 4.3:1 at the token level to keep 3:1 on its darkest face.

## Performance budgets

- One draw call per mesh: fewer than 100 for a widget. Share geometries and use one material per state.
- Zero frames while idle. The viewer renders on demand; a scene change that React does not see calls `invalidate()`.
- `renderer.info.memory` stays flat when the selection changes, the theme changes, and the viewer remounts.
- `data-render-stats` on the viewer shows `calls`, `triangles`, `geometries`, `textures`, `frames`, and `idle`.

## Assets and licenses

Prefer procedural models: capsules, spheres, and lathed profiles need no files and no license. A product that needs a real model:

- MakeHuman exports and Quaternius models are CC0.
- Z-Anatomy is CC BY-SA, which is copyleft: do not put it in the template.
- NIH 3D licenses vary per model; reject NC (non-commercial) and ND (no derivatives).
- Self-host every file. If you use `useGLTF`, call `useGLTF.setDecoderPath` with your own copy of the Draco decoders: drei's default fetches them from a Google CDN, which fails in the offline desktop app.

## Testing

- Unit-test the pure parts: the region model, the view reducer, and token parsing.
- jsdom has no WebGL: test the fallback there.
- In a browser: read `data-render-stats` (draw calls, idle frames), run axe in light and dark and at 375px, walk the keyboard path, emulate reduced motion, and launch Chromium with `--disable-webgl` for the fallback.
